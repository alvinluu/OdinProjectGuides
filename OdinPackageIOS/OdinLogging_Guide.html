1. Overview

OdinPackageIOS provides a unified logging system with three destinations:

DestinationWhat it doesActor
ConsolePrints to Xcode console with symbol, filename, and line number—
PortablePOSTs the log entry to the remote Portable log tablePortableLog
EmailSends an email alertEmailLog
DiagnosticAppends to odin_diagnostic.log in the app's Documents folderDiagnosticLog

Every log call starts with Log.<type>("message"), which always goes to the console. Additional destinations are chained off the result.

2. Setup

Configure at Launch

Call OdinDiagnosticKit.configure once in your app entry point (e.g. AppDelegate or the @main struct).

await OdinDiagnosticKit.configure(
    log: .bifrost(
        env: .live,
        deviceIdentifier: device.serialNumber,
        school: "MyApp",
        mirrorToOSLog: false,
        osLogSubsystem: "com.odin-inc.myapp"
    ),
    email: .bifrost(
        senderAddress: "myapp@odin-inc.com",
        defaultRecipients: ["support@odin-inc.com"]
    )
)

OdinLogConfig.bifrost(...) and OdinEmailConfig.bifrost(...) are convenience factories that fill in the Bifrost endpoint URLs for you. You can also construct either config directly (OdinLogConfig(endpoint:deviceIdentifier:...) / OdinEmailConfig(backendEndpoint:senderAddress:defaultRecipients:...)) if you're pointing at a non-Bifrost endpoint.

OdinLogConfig parameters

ParameterDescription
env.live or .test — selects the Bifrost endpoint
deviceIdentifierSerial number or device ID included in every Bifrost payload
schoolIncluded in every Bifrost payload; defaults to an empty string
mirrorToOSLogSet false when your app also logs to os.Logger (avoids duplicate console output)
osLogSubsystemBundle ID used as the os.Logger subsystem
localLogEnabledDefaults to true — writes every log to the portable file automatically
maxRequestsPerMinuteRate limit for Bifrost posts; see Rate Limiting

OdinEmailConfig parameters

ParameterDescription
env.live or .test — selects the Bifrost email endpoint
senderAddress"From" address on outgoing emails
defaultRecipientsUsed when a call site doesn't pass recipients: explicitly
defaultBCCAdditional default BCC addresses, merged with the recipients passed at the call site
supportsInAppMailSet true to enable makeInAppMailComposer(...) for presenting MFMailComposeViewController in-app
maxRequestsPerMinuteRate limit for email sends; see Rate Limiting
systemBCCAlways BCC'd on every email, in addition to any defaultBCC or per-call bcc:. Defaults to ["alvin@odin-inc.com"]
Tip: systemBCC defaults to alvin@odin-inc.com so Odin can spot-check email delivery across apps. Override it at configure time if your app shouldn't BCC that address:
email: .bifrost(
    senderAddress: "myapp@odin-inc.com",
    defaultRecipients: ["support@odin-inc.com"],
    systemBCC: []   // or ["your-team@odin-inc.com"]
)

Updating the Device Identifier

If the device identifier is only known after login (e.g. MKS), call updateDeviceIdentifier once authentication completes:

await OdinDiagnosticKit.updateDeviceIdentifier(user.deviceId)

All subsequent Bifrost payloads will use the updated value.

Defining App Log Tags

Each app defines its own enum conforming to BifrostTaggable. The raw value must match a valid Bifrost LogTags enum name. Pass the enum as the generic parameter when declaring Log — Swift then infers the tag type at every call site so you can omit the enum prefix.

// Define the app's tags (e.g. in Log.swift)
enum InventoryTag: String, BifrostTaggable {
    case Inventory
    case StockUpload
    case InventoryAppEmail
    case InventoryImport
    case InventoryImportPreview
    case Error
}

// Declare Log once with the tag enum
let Log = LogNamespace<InventoryTag>()

// Usage — no prefix needed
Log.network("Upload failed").portable(.StockUpload)
Log.network("Login failed").portable(.Error)
Tip: Each app declares its own Log with a different tag enum (e.g. LogNamespace<MKSTag>). Xcode autocomplete only shows that app's tags. The full reference list is in BifrostLogTag.swift.

Rate Limiting

PortableLog and EmailLog each throttle their outgoing network requests with a token-bucket RateLimiter. Calls beyond the limit are delayed until a slot frees up rather than dropped — a runaway logging loop or alert burst gets smoothed out instead of flooding the backend, and no entries are lost.

ConfigParameterDefaultThrottles
OdinLogConfigmaxRequestsPerMinute60.portable(_:) posts
OdinEmailConfigmaxRequestsPerMinute20.email() sends
OdinLogConfig(
    endpoint: bifrostURL,
    deviceIdentifier: device.serialNumber,
    maxRequestsPerMinute: 60   // defaults to 60
)

OdinEmailConfig(
    backendEndpoint: emailURL,
    senderAddress: "noreply@odin-inc.com",
    defaultRecipients: ["support@odin-inc.com"],
    maxRequestsPerMinute: 20   // defaults to 20
)
Tip: Console output and diagnostic-file writes are not rate limited — only network requests to the Bifrost log table and the email backend are throttled.

3. Logging

Console Only

Call Log.<type>("message"), or call Log("message") directly when the type doesn't matter. The result can be discarded.

Log("App launched")                          // general type, no type selection needed
Log.network("Download started")
Log.data("Saved \(items.count) items")
Log.settings("Theme changed to dark")
Log.scanner("Barcode scanned: \(barcode)")

Console output format:

🌐 [TransferView.swift:142] Download started

Console + Remote Log Table

Chain .portable(_:) to post to the matching server-side log table. Because Log is declared with a specific tag enum, the enum prefix is not needed — Xcode autocompletes the cases directly.

Log.network("Upload complete").portable(.StockUpload)
Log.network("Import finished").portable(.InventoryImport)

// Pass detail: to append extra context beyond the original log message
Log.network("Upload failed").portable(.StockUpload, detail: "Retry count: 3, HTTP 503")
Note: The tag's raw value must match a valid LogTags enum name on the server. Use your app's scoped enum to avoid typos.

Console + Email Alert

Chain .email() to send an email alert. Subject is derived from the log type. Pass cc: to copy an additional address, detail: to append extra context to the body, and attachment: to include a file.

Log.network("Critical sync failure").email()
Log.network("Upload failed").email(cc: "develop@odin-inc.com")
Log.network("Upload failed").email(detail: "Retry count: 3, HTTP 503")

let attachment = OdinEmailAttachment(data: exportData, fileExtension: "csv")
Log.data("Export failed").email(attachment: attachment)
Note: OdinEmailAttachment only takes data and fileExtension (e.g. "csv", "pdf", "log") — no filename or MIME type field exists, because the Bifrost backend derives both itself from subject + "." + fileExtension and doesn't accept them from the client. Passing a filename or MIME type here wouldn't do anything; the field names have to match what the server actually reads.

The chained .email() fires and forgets — the result is discarded. When you need to know whether the email was sent successfully, call EmailLog.shared.sendEmail directly with a completion block:

EmailLog.shared.sendEmail(
    subject: "Upload Failed",
    body: "Stock upload failed for device \(serial)",
    cc: ["develop@odin-inc.com"]
) { success, error in
    if success {
        print("Email sent")
    } else {
        print("Email failed: \(error?.localizedDescription ?? "unknown")")
    }
}
Tip: The completion block runs on a background thread. Dispatch to the main thread before updating UI.

Console + Diagnostic File

Chain .diagnostic() to write to the local odin_diagnostic.log file on the device.

Log.data("Export completed").diagnostic()
Tip: When localLogEnabled: true (the default), every .portable(tag) call already writes to the diagnostic file automatically — you only need .diagnostic() when logging to the file without also posting to the remote log.

Chaining Destinations

Destinations can be combined in any order. Console is always first.

// Console + remote log table
Log.network("Stock upload failed").portable(.StockUpload)

// Console + remote + Email
Log.network("Upload failed").portable(.StockUpload).email()

// Console + remote + diagnostic file
Log.data("Import complete").portable(.Inventory).diagnostic()

// Console + remote + Email + diagnostic file
Log.network("Critical error").portable(.Error).email().diagnostic()

Silent (No Console)

Use Log.silent.<type> to skip console output entirely. The returned LogEntry supports the same chaining — useful for high-frequency events or background tasks where console noise isn't wanted.

// Remote log only — no console output
Log.silent.network("Heartbeat sent").portable(.Inventory)
Log.silent("Heartbeat sent").portable(.Inventory)  // general type shorthand

// Email only — no console output
Log.silent.network("Auth token expired").email()

// Remote + Email — no console output
Log.silent.network("Upload failed").portable(.StockUpload).email()
Tip: Log.silent still writes to the diagnostic file when localLogEnabled is true and you chain .diagnostic(), or when PortableLog writes automatically on a .portable() call.

Log + Email an Error in One Call

For error paths that should both post to the remote log table and immediately email a developer, call OdinDiagnosticKit.reportError instead of chaining .portable() and .email() separately. It posts with the Error tag and sends an email that includes device/app version info automatically.

try await OdinDiagnosticKit.reportError(
    "Stock upload failed for device \(serial)",
    type: OdinLogType.error,
    emailSubject: "[MyApp] Stock Upload Failure",
    attachment: OdinEmailAttachment(
        data: await DiagnosticLog.shared.export() ?? Data(),
        fileExtension: "log"
    )
)
Tip: This calls EmailLog.shared.sendEmail under the hood (the same call used by .email()), after prepending app version, build, and device info to the body. Pass attachment: to include a file (e.g. an exported diagnostic log) — see Console + Email Alert above for why OdinEmailAttachment only takes fileExtension, not a filename or MIME type.

4. Diagnostic Log (Local File)

The portable log writes timestamped entries to odin_diagnostic.log in the app's Documents directory. It trims to the last 500 entries when it reaches 1,000 lines.

Reading and Exporting

// Export as Data (e.g. to attach to an email)
let data = await DiagnosticLog.shared.export()

// File size in bytes
let size = await DiagnosticLog.shared.fileSize()

// Clear the log
await DiagnosticLog.shared.clear()

SettingsView Integration

In InventoryTracker, the Settings → Diagnostics section provides buttons to email or clear the portable log. This is the recommended pattern for other apps too.

Define only the tags your app uses in a scoped BifrostTaggable enum. See Defining App Log Tags above.
