1. Overview

SearchBarcodeV2 detects whether input arriving in a text field came from a barcode scanner (fast, automatic) or a human typing (slow, deliberate). When a scan is detected it emits the barcode via both a NotificationCenter notification and an AsyncStream, then resets automatically.

It is a singleton (SearchBarcodeV2.shared) and is thread-safe — all internal state is protected by a serial DispatchQueue.

How Detection Works

  1. Every text-field change calls search(_:).
  2. The time since the last call is measured. If it is below kScannerDetectionSpeed (default 0.055 s), it counts as a fast keystroke.
  3. Once kMinFastInputs (2) consecutive fast keystrokes accumulate, isSearchingWithScanner turns true.
  4. A 0.1 s timer is scheduled on every fast input. When it fires with no new input, the full field text is emitted as the barcode.
  5. Slow input while not scanning captures the text as preScanText and posts .searchBarcodeTypingDetected.
  6. Clearing the field cancels the pending scan and resets all state.

2. Setup

No configuration is required. Call resetAll() when the view (re)appears to clear any stale timing state from a previous session.

// In onAppear / viewDidAppear
SearchBarcodeV2.shared.resetAll()
Tip: kScannerDetectionSpeed is persisted via UserDefaults — it survives app restarts and adapts over time. You do not need to set it manually.

3. Usage

NotificationCenter (existing apps)

Register observers for .searchBarcodeSearchingStart and optionally .searchBarcodeTypingDetected. Call search(_:) on every text-field change. Call endSearch() after handling the barcode.

// Register observers once (e.g. in init or onAppear)
NotificationCenter.default.addObserver(
    forName: .searchBarcodeSearchingStart,
    object: nil,
    queue: .main
) { _ in
    let barcode = SearchBarcodeV2.shared.searchedText
    // handle barcode...
    SearchBarcodeV2.shared.endSearch()
}

NotificationCenter.default.addObserver(
    forName: .searchBarcodeTypingDetected,
    object: nil,
    queue: .main
) { _ in
    // user is typing — update UI if needed
}

// In your text field onChange
SearchBarcodeV2.shared.search(searchText)

AsyncStream (modern)

Observe scanEvents in a Task. Each confirmed barcode is emitted as a String. Call endSearch() after handling.

Task {
    for await barcode in SearchBarcodeV2.shared.scanEvents {
        await MainActor.run {
            // handle barcode on main thread
            SearchBarcodeV2.shared.endSearch()
        }
    }
}
Tip: Every call to scanEvents returns an independent stream — multiple observers each get their own copy of the event.

Stripping the Typed Prefix

When the user types part of a barcode manually before the scanner fires, preScanText captures the field content at the moment slow input was last detected. The first scanner character always arrives slow (interrupting the typing pace), so preScanText includes it. Drop the last character to recover the pure typed prefix, then strip it from searchedText.

let barcode = SearchBarcodeV2.shared.searchedText
let prefix = String(SearchBarcodeV2.shared.preScanText.dropLast())
let cleaned = barcode.hasPrefix(prefix) ? String(barcode.dropFirst(prefix.count)) : barcode
Note: If the user did not type anything before scanning, preScanText is empty and no stripping is needed.

Short Barcodes

Some barcodes are only 2–3 characters. With the default threshold of 2 consecutive fast inputs, the scanner may not be detected before the barcode ends. Enable short-barcode mode to lower the threshold to 1:

SearchBarcodeV2.shared.hasShortBarcode = true
Note: Enabling this increases the chance of fast typers being misdetected as scanners. Only use it when your barcode set is consistently short.

6. Adaptive Speed Tuning

V2 tracks a rolling window of the last 20 scan outcomes. A scan is a success when the barcode is emitted normally. It is a failure when the field is cleared mid-scan (search("") called before the timer fires) or when the emitted text is shorter than kMinBarcodeLength.

When the failure rate reaches 10% across the window, kScannerDetectionSpeed is automatically increased by 0.005 s (capped at 0.1 s) and persisted to UserDefaults. This compensates for slower scanners or high-latency Bluetooth connections without any manual tuning.

ParameterValueDescription
Default speed0.055 sInitial inter-keystroke threshold
Step size+0.005 sIncrease applied when failure rate is too high
Maximum speed0.1 sUpper bound — prevents misdetecting fast typists

Tip: You can read successCount and failureCount for diagnostics, but there is no need to reset or adjust them manually — the adaptive logic handles everything.
