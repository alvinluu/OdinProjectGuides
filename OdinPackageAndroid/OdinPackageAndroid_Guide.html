1. Overview

OdinPackageAndroid is the Android equivalent of OdinPackageIOS. It provides chainable logging, email alerts, local diagnostic file storage, and barcode scanner detection — all posting to the same Bifrost backend endpoints.

What's Included

Class / ObjectDescription
PortableLogPosts log entries to the remote Bifrost log table via HTTP
DiagnosticLogWrites timestamped entries to a local .log file on device storage
EmailLogSends email alerts through the Bifrost email endpoint
LogEntry<Tag>Chainable entry returned by every log call — attach destinations with .portable(), .email(), .diagnostic()
SearchBarcodeV2Detects barcode scanner input vs keyboard typing by analysing keystroke speed
OdinDiagnosticKitOne-call setup for all three logging singletons

2. Setup

Gradle

Add the module to your project's settings.gradle.kts and include it as a dependency in your app module.

// settings.gradle.kts
includeBuild("../OdinPackageAndroid")

// app/build.gradle.kts
dependencies {
    implementation("com.odininc:OdinPackageAndroid")
}
Tip: The only transitive dependency is kotlinx-coroutines-android. All networking uses the standard HttpURLConnection from the JDK.

Configure

Call OdinDiagnosticKit.configure() once at app startup — typically in Application.onCreate(). This initialises PortableLog, EmailLog, and optionally DiagnosticLog.

class MyApp : Application() {
    override fun onCreate() {
        super.onCreate()
        val logConfig = OdinLogConfig.bifrost(
            deviceIdentifier = getSerialNumber(),
            localLogEnabled = true
        )
        val emailConfig = OdinEmailConfig.bifrost(
            senderAddress = "noreply@odin-inc.com",
            defaultRecipients = listOf("aldin@odin-inc.com")
        )
        lifecycleScope.launch {
            OdinDiagnosticKit.configure(logConfig, emailConfig, filesDir)
        }

        // Configure barcode scanner speed persistence
        val prefs = getSharedPreferences("odin_prefs", MODE_PRIVATE)
        SearchBarcodeV2.shared.configure(prefs)
    }
}

After the user logs in and a device identifier is known, update it:

lifecycleScope.launch {
    OdinDiagnosticKit.updateDeviceIdentifier(serial)
}

3. Logging

Define App Tags

Each app defines its own enum implementing BifrostTaggable. The rawValue must match a valid LogTags enum name on the Bifrost server.

enum class InventoryTag(override val rawValue: String) : BifrostTaggable {
    Inventory("Inventory"),
    StockUpload("StockUpload"),
    InventoryImport("InventoryImport"),
    InventoryImportPreview("InventoryImportPreview"),
    Error("Error")
}

// Declare once per app — instantiate with the tag type
val Log = LogNamespace<InventoryTag>(tag = "InventoryTracker")
Tip: Keeping the enum scoped to your app means you only see tags relevant to that project in autocomplete.

Console Only

Every Log.*("message") call logs to Logcat immediately and returns a LogEntry<Tag>. Discard the return value to log to console only.

Log.network("Download started")
Log.data("Saved 142 items")
Log.error("Validation failed")

Console + Remote Log

Chain .portable(tag) to post to the matching Bifrost log table. No enum prefix is needed when the tag type is fixed by the LogNamespace declaration.

Log.network("Download complete").portable(InventoryTag.Inventory)
Log.network("Upload failed").portable(InventoryTag.Error)

Console + Email Alert

Chain .email() to send an email alert. Pass cc to copy an additional address.

Log.network("Critical sync failure").email()
Log.network("Upload failed").email(cc = "develop@odin-inc.com")

Console + Diagnostic File

Chain .diagnostic() to write to the local odin_diagnostic.log file.

Log.data("Export completed").diagnostic()
Tip: When localLogEnabled = true, every .portable(tag) call already writes to the diagnostic file automatically via PortableLog. Use .diagnostic() only when writing to the file without also posting to the remote log.

Chaining Destinations

Destinations can be combined in any order.

// Console + remote log table
Log.network("Stock upload failed").portable(InventoryTag.StockUpload)

// Console + remote + email
Log.network("Upload failed").portable(InventoryTag.StockUpload).email()

// Console + remote + diagnostic file
Log.data("Import complete").portable(InventoryTag.Inventory).diagnostic()

// Console + remote + email + diagnostic file
Log.network("Critical error").portable(InventoryTag.Error).email().diagnostic()

4. SearchBarcodeV2

Call SearchBarcodeV2.shared.search(text) on every TextWatcher.onTextChanged event. The singleton detects scanner vs typing speed and fires the barcode via listener or Flow.

Listener (traditional)

Register a ScanListener for the barcode event. Call endSearch() after handling it. Listeners fire on the main thread.

SearchBarcodeV2.shared.addScanListener { barcode ->
    handleBarcode(barcode)
    SearchBarcodeV2.shared.endSearch()
}

SearchBarcodeV2.shared.addTypingListener {
    // user is typing — update UI if needed
}

// Wire to TextWatcher
searchField.addTextChangedListener(object : TextWatcher {
    override fun onTextChanged(s: CharSequence?, start: Int, before: Int, count: Int) {
        SearchBarcodeV2.shared.search(s?.toString() ?: "")
    }
    override fun beforeTextChanged(s: CharSequence?, start: Int, count: Int, after: Int) {}
    override fun afterTextChanged(s: Editable?) {}
})

Flow (coroutines)

Collect scanEvents in a coroutine. Call endSearch() after handling each emission.

lifecycleScope.launch {
    SearchBarcodeV2.shared.scanEvents.collect { barcode ->
        handleBarcode(barcode)
        SearchBarcodeV2.shared.endSearch()
    }
}

Stripping the Typed Prefix

When the user types part of a barcode before the scanner fires, preScanText captures the field content at the last slow keystroke — including the first scanner character which always arrives slow. Drop the last character to get the pure typed prefix, then strip it from searchedText.

val barcode = SearchBarcodeV2.shared.searchedText
val prefix = SearchBarcodeV2.shared.preScanText.dropLast(1)
val cleaned = if (barcode.startsWith(prefix)) barcode.drop(prefix.length) else barcode
Note: Call resetAll() in onResume() to clear any stale timing state from a previous session.

5. DiagnosticLog

The diagnostic log file is stored in the app's filesDir as odin_diagnostic.log. It is trimmed automatically to maxEntries (default 1000) lines when it exceeds that limit.

// Export as bytes (e.g. to attach to an email)
lifecycleScope.launch {
    val bytes = DiagnosticLog.export()
    if (bytes != null) {
        val attachment = OdinEmailAttachment(bytes, "text/plain", "odin_diagnostic.log")
        EmailLog.sendTroubleshootEmail(
            subject = "Diagnostic Log — ${BuildConfig.VERSION_NAME}",
            attachment = attachment
        )
    }
}

// Clear the log file
lifecycleScope.launch { DiagnosticLog.clear() }

// Check file size in bytes
lifecycleScope.launch {
    val size = DiagnosticLog.fileSize()
    Log.data("Diagnostic log: $size bytes")
}
