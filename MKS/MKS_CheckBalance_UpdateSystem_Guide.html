1. How the Update System Works

Updates are controlled from the server, per device, and delivered from your own Bifrost host (not Google Play). The flow:

  1. On launch the app checks in to portable.ipadconfig (via the existing IPadConfig endpoint), recording its serial, school and current version.
  2. It reads its row's available_update_version and force_update columns (via BalanceCheckerUpdate).
  3. If available_update_version is newer than what's installed:
    • force_update = 1 → it updates automatically on launch (no prompt, no PIN).
    • Otherwise staff use Check for updates in the version dialog (admin-PIN-gated).
  4. To download, the app gets a one-time download password (BalanceCheckerDownloadKey), then POSTs it to DownloadBalanceCheckerAppUpdate, which streams mks-checkbalance-<version>.apk.
  5. The app installs it and relaunches.

You roll out an update by hosting the new APK and editing the device's row in portable.ipadconfig.

EndpointPurpose
POST api/IPadConfigDevice check-in (stores app info).
POST api/BalanceCheckerUpdateReturns available_update_version + force_update.
POST api/BalanceCheckerDownloadKeyReturns the update download password (from rights).
POST api/DownloadBalanceCheckerAppUpdatePassword-gated APK download (the update).
POST api/DownloadBalanceCheckerPassword-gated installer download (first install, web page).

2. Server Setup (Bifrost)

Deploy the endpoints

1 Pull the latest Bifrost (branch master) and build it in Visual Studio on Windows (net472 — it can't build on macOS).
2 Publish/deploy to your server (live msdata.co or test 54.167.168.76).
net472 note: the four new controllers are listed explicitly in Bifrost.csproj (<Compile Include…>). If a new controller ever 404s, it's almost always missing from the csproj.

Add columns & passwords

a. Add the two columns to portable.ipadconfig

ALTER TABLE portable.ipadconfig
    ADD COLUMN available_update_version VARCHAR(50) NULL DEFAULT NULL AFTER pend_tran,
    ADD COLUMN force_update             TINYINT(1)  NOT NULL DEFAULT 0 AFTER available_update_version;

b. Add the two download passwords to MKSdata.rights

Password A gates the installer download; password B gates the app update download. Both are encrypted with the standard rights key (the value CryptoHelper.SECRET_KEY4 holds) — substitute it for <RIGHTS_KEY>.

-- Password A: installer web download (userid BCDownload)
INSERT INTO MKSdata.rights (userid, school, rightstype, pin, password, firstname, lastname, lastupdate)
VALUES ('BCDownload','Odin','BalanceChecker',
        AES_ENCRYPT('','<RIGHTS_KEY>'), AES_ENCRYPT('<INSTALL_PW>','<RIGHTS_KEY>'),
        'Balance','Installer', NOW());

-- Password B: app auto-update download (userid BCUpdate)
INSERT INTO MKSdata.rights (userid, school, rightstype, pin, password, firstname, lastname, lastupdate)
VALUES ('BCUpdate','Odin','BalanceChecker',
        AES_ENCRYPT('','<RIGHTS_KEY>'), AES_ENCRYPT('<UPDATE_PW>','<RIGHTS_KEY>'),
        'Balance','Updater', NOW());
The rights school is Odin here — it must match CheckBalance.RightsSchool below. The app never stores password B; it fetches it from BalanceCheckerDownloadKey at update time.

Web.config & hosting the APKs (S3)

APKs are stored in a private S3 bucket (odin-app-balancechecker) and streamed by Bifrost using the server’s IAM credentials — the bucket stays private, so the password is the only way to download. Add to Bifrost’s <appSettings>:

<add key="CheckBalance.RightsSchool" value="Odin" />
<add key="CheckBalance.S3Bucket"     value="odin-app-balancechecker" />
<add key="CheckBalance.S3Region"     value="us-east-1" />
<add key="CheckBalance.S3KeyPrefix"  value="" />               <!-- bucket root -->
<add key="CheckBalance.InstallerKey" value="mks-checkbalance-latest.apk" />
  • Prerequisites (once): NuGet-install AWSSDK.S3 (4.0.x) in Visual Studio, and grant the .76 EC2’s IAM role s3:GetObject on arn:aws:s3:::odin-app-balancechecker/*.
  • Upload each release’s APK to the bucket named mks-checkbalance-<version>.apk (the version must match available_update_version). Example: mks-checkbalance-1.0.1.apk.
  • The download page serves InstallerKey — keep a stable mks-checkbalance-latest.apk object and overwrite it each release so the page always hands out the newest build (aws s3 cp …-1.0.1.apk …-latest.apk).
The download page (download/balancechecker.html) ships with the Bifrost deploy (it’s a project Content file), so a redeploy never wipes it. The APKs live in S3, outside the deploy entirely.

3. Build & Install the App

1 Build the signed release APK: 
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
export ANDROID_SDK_ROOT=/opt/homebrew/share/android-commandlinetools
export PATH="$JAVA_HOME/bin:$ANDROID_SDK_ROOT/platform-tools:$PATH"
cd mks_balance
flutter build apk --release
# → build/app/outputs/flutter-apk/app-release.apk
2 Install on the device (USB debugging on): 
adb install -r build/app/outputs/flutter-apk/app-release.apk
3 Launch it, run Device Setup (register with a school code) so the device creates its portable.ipadconfig row on first check-in.
Version naming: the app compares by version name (e.g. 1.0.0). To test an update you'll host a higher one (1.0.1) — build it with flutter build apk --release --build-name=1.0.1 --build-number=3 and rename the output to mks-checkbalance-1.0.1.apk.

4. (Optional) Enable Silent, Zero-Tap Updates

By default the download is automatic but the install shows one confirmation tap. To make installs fully silent, the app must be the device's device owner — a one-time setup done over a cable on a freshly reset device with no accounts.

Requirements: device owner can only be set with zero accounts on the device. On a generic device (no vendor staging tool, no Google setup wizard), the only route is adb over a cable — do it once, then never again.
1 Factory reset; do not add any Google account. Enable USB debugging.
2 Install the app (Section 3), then set device owner: 
adb shell dpm set-device-owner com.odin.balancechecker/com.odininc.mks_balance.AppDeviceAdminReceiver
3 Expect Success: Device owner set…. Verify in-app: tap the version number → Silent update: On (device owner).

Once device owner, every update (forced or manual) installs with zero taps. If set-device-owner is refused (accounts present, or already set up), remove all accounts / factory reset and retry. If silent isn't possible, the one-tap flow still works — nothing else changes.

5. Test the Update on Your Device

1 Confirm the device checked in — its row exists: 
SELECT serial, school, appversion, available_update_version, force_update
FROM portable.ipadconfig WHERE serial = '<DEVICE_SERIAL>';
(Find the serial in-app: tap the version number → Serial.)
2 Upload a newer APK, e.g. mks-checkbalance-1.0.1.apk, to the S3 bucket.
3 Point the device's row at it: 
UPDATE portable.ipadconfig
SET available_update_version = '1.0.1', force_update = 0
WHERE serial = '<DEVICE_SERIAL>';
4 Manual test: in the app, tap the version number → Check for updates → enter the admin PIN → it downloads and installs 1.0.1 (one tap, or silent if device owner) → app relaunches showing v1.0.1.
5 Forced test: set force_update = 1, then relaunch the app. It should download and install automatically with no prompt.
Confirming it worked: the version number (top-right) now reads the new version, and appversion in the device's ipadconfig row updates on the next check-in.

6. Troubleshooting

SymptomLikely cause / fix
"Could not check for updates"Device can't reach Bifrost, or BalanceCheckerUpdate not deployed. Check network + that the controller is in Bifrost.csproj.
Says "up to date" when it shouldn'tavailable_update_version isn't higher than the installed version name, or the row wasn't updated for this serial.
"Could not authorize the update download"BalanceCheckerDownloadKey returned nothing — the BCUpdate rights row is missing or under the wrong school (must equal CheckBalance.RightsSchool).
"Update failed: HTTP 401"Password mismatch — the rights password doesn't decrypt to what the app sent (wrong key or wrong row).
"Update failed: HTTP 404"No mks-checkbalance-<version>.apk in the S3 bucket for that version (wrong key/prefix), or the object was deleted.
"Download error" / 500 on downloadBifrost can't reach S3 — the EC2 IAM role lacks s3:GetObject on the bucket, or CheckBalance.S3Bucket/S3Region is wrong, or AWSSDK.S3 isn't installed.
Install prompt appears (not silent)Device isn't device owner — see Section 4. Expected on non-provisioned devices.
"There was a problem parsing the package"The hosted APK is corrupt or not the release-signed build.
Update installs but won't replace the appSignature mismatch — the hosted APK must be signed with the same key as the installed build.
