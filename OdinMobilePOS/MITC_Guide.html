1. Overview

MITC (MeetInTheCloud) is one of the credit-card gateways supported by the Credit screen, the same charge screen used for Square, TSYS, and NMI. When the school's merchant is configured as MITC, the Credit screen automatically routes sales, refunds, and voids through the MITC gateway using the physical payment terminal.

Tip: The Credit screen looks and behaves the same regardless of merchant — the amount you enter, the Process button, and the Cancel/Close buttons work the same way. This guide only covers the MITC-specific behavior: gateway status messages, the Cancel Device button, and the refund/void flow.

2. Merchant Setup

Before MITC can be used, it must be configured in Setting > Configuration > Credit Card Setting:

1 Set Merchant to MITC.
2 Enter the Merchant Key field.
3 Enter the Device ID for the payment terminal.
4 Set the Currency if needed (this field becomes editable only for MITC).
Note: If any of Merchant Key, Merchant Secret, or Device ID is missing, the Credit screen will show an alert (“MITC Account Not Filled” or “MITC Device Not Set”) the moment you try to process a sale, telling you exactly which field to fix.

Verifying Setup with MITCTestView

Once Merchant is set to MITC TEST (the sandbox merchant), a Test MITC button appears in Credit Card Setting. Tapping it opens MITCTestView — a self-contained debug screen for exercising the gateway directly, without ringing up a cart or creating a real sale record.

1 On the Credit Card Setting screen, with Merchant set to MITC TEST, tap Test MITC.
2 The screen runs a health check automatically on open. Environment confirms Sandbox mode, base URL, and the Key/Secret currently saved; Configuration shows the Device ID, Amount, Reference, and Invoice # that will be used.
3 Tap Process Sale to run a full sandbox sale, then tap the resulting row in Transaction History to select it.
4 With a transaction selected, use Void Selected or Refund Selected to test those flows the same way they behave on the real Credit screen.
Tip: Each request/response pair is shown at the bottom of the screen (Raw Request / Raw Response) — the fastest way to confirm the Merchant Key, Secret, and Device ID are correct before switching Merchant to production MITC. A retried sale after a failure automatically appends a letter to the reference (A, B, C…) so it won't collide with the failed attempt.
Note: Test MITC / MITCTestView only appears for the sandbox merchant MITC TEST. Switch Merchant to production MITC once setup is verified — the test button will no longer be available.

3. Ringing Up an Item for Sale

1 Ring up the item(s) in the cart as usual, then tap the credit card payment button to open the Credit screen with the total amount filled in.
2 The Credit screen checks the gateway automatically. Wait for the status to read “Device ready. Tap Process to begin payment. Invoice: 000123” (the invoice number shown is whatever will actually be sent on this Process tap).
3 Tap Process. The terminal will prompt the customer to tap/insert/swipe their card. The status line counts up while waiting: “Follow the prompts on the payment device… 4s”.
4 On approval, the status becomes “Approved {approval code} {masked card number}” and the sale is recorded automatically.
Note: If the customer doesn't complete the card prompt within 15 minutes, the request will time out and the sale will fail. Use Cancel Device (below) if you need to stop waiting sooner, then tap Process again to retry.

Cancel Device

The Cancel Device button appears below Process at all times for MITC merchants. Use it if the terminal gets stuck waiting for a card (e.g. the customer walked away, or the terminal froze). Tapping it asks the gateway to cancel the pending prompt; the status changes to “Cancel sent. Waiting for the terminal to confirm…”.

Tip: Cancel Device works even if you didn't just attempt a sale on this screen — it will try to clear whatever the last reference used was, so it can also recover a terminal left stuck from an earlier session.

Adding a Note to the Sale

If “Add note to CC sale” is turned on in Credit Card Settings, the Credit screen stays open after an approved sale so you can type a note (and select a patron, if required) before finishing. The Process button changes to Finish — tap it to save the sale and close the screen. If that setting is off, the sale saves and closes automatically as soon as it's approved.

4. Processing a Refund

To refund a MITC sale, open the Credit screen and enter the refund amount as a negative number.

Looking Up the Original Sale

1 With a negative amount entered, the status reads: “REFUND: The last 4 digits of the card are required. Type them into the card number field, then tap Look Up to find the original sale.”
2 Type the last 4 digits of the card into the card number field.
3 Tap Look Up (the Process button, retitled). This opens the transaction history for that card so you can pick the original sale.
4 Select the correct sale from the list.
Note: If the amount you're refunding is more than the original sale, or if you accidentally pick another refund instead of a sale, the Credit screen will reject the selection and send you back to Look Up with an explanation in the status line.

Submitting the Refund

Once a valid original sale is selected, the Credit screen automatically submits the refund. Status reads “Processing refund. Please wait…”, then:

  • Success: “Refund Approved {approval code} {card}” — the refund is recorded and the screen closes.
  • Failure: “Refund {status}: {message}” with the original sale's Trans ID and Ref shown underneath. The Process button changes to Transaction Detail (see Section 6) instead of retrying automatically. If the gateway indicates the transaction needs to be voided instead (see below), the Void button also appears.

Refund vs. Void

Important business rule:
  • Refund — should only be performed on transactions that are in a closed batch (settled).
  • Void — if the sale is still open (not settled), submit a Void request instead.

This guidance is shown directly in the status line whenever a refund becomes available, so you don't need to remember it — but it's worth understanding why: refunding a same-day, unsettled sale is not the correct operation on this gateway.

Tip: Settlement takes at least 1 day. In practice, this means a same-day sale will not yet be settled — use Void (see Section 5) for anything rung up today. Refund only becomes the correct option once the sale is at least a day old and has settled.

5. Voiding a Transaction

The Void button only appears after a refund attempt fails in a way that indicates the sale needs to be voided instead — for example, when the gateway reports the transaction was already completed/refunded previously. It is hidden the rest of the time.

1 After a failed refund shows the Void button, tap Void.
2 Void targets the original sale you looked up for the refund (not the failed refund attempt itself).
3 On success, status reads “Void Approved {approval code} {card}” and the screen closes automatically.
4 On failure, the button stays available so you can try again, and the status line explains what went wrong (gateway, network, or validation error).

6. Transaction Detail Lookup

After a refund fails, the Process button changes to Transaction Detail. Tapping it looks up the original sale directly from the MITC gateway and shows a side-by-side comparison:

  • Gateway Report — live data from MITC: status, success/fail, transaction ID, reference, approval code, card, amount, and message.
  • Original Sale — what Odin recorded locally for that sale: date, amount, cardholder, card last 4, transaction ID, reference, invoice, type, approval, and response.

Use this when a refund or void keeps failing and you need to confirm what the gateway actually has on file for that sale before escalating.
