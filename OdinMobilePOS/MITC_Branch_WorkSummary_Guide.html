1. Overview & scope

This branch adds a full MeetIntheCloud (MITC) card-present payment gateway integration to Odin Mobile POS, replacing the need to bridge the .NET PaymentGateway.Integration DLL. MITC is a plain HTTPS + JSON gateway; the app talks to it directly over the wire and drives a physical pinpad terminal (Genius / Tetra Lane) — the iPad does not read the card itself.

Alongside the gateway itself, the branch delivered the surrounding POS plumbing: sale/refund/void/cancel flows, transaction lookup and reporting, an invoice counter, a toggle to disable the credit card fee, richer error-email diagnostics, and a mock/test mode. It also merged in the sync-engine branch, which brought the Square payment coordinator and a new unified sync subsystem.

2. MITC payment gateway package

The gateway lives in a self-contained local Swift Package, Packages/PaymentGateway.iOS, added to Xcode via File → Add Packages → Add Local… and imported as import MeetIntheCloud (iOS 13+ for CryptoKit). The package deliberately mirrors the .NET library's separation of concerns so the two stay easy to read side-by-side.

Package layers

FileLayerResponsibility
MeetIntheCloudAuth.swiftAuthBuilds the signed Authorization token (AuthTokenV2 = JWT + HMAC-SHA256, Base64URL). Pure, stateless, testable (inject nowMillis). Never does I/O.
MeetIntheCloudModels.swiftModelsConfig, Codable request/response DTOs, the app-facing TransactionResult, and the status normalizer. No dependencies, no I/O.
MeetIntheCloudClient.swiftClientThe only place that touches URLSession. Endpoint routing, header assembly, the X-GP-Target-Device terminal rule, request/response mapping, error shaping. Public operations: sale, auth, refund, dependent refund, void, cancel, health.

Public surface is MeetIntheCloudConfig, MeetIntheCloudClient, TransactionResult, and MeetIntheCloudError — everything else is internal.

Behavior notes baked into the client: allowDuplicate = true, countryCode = "840", language = "en-US", create_token = true with reason unscheduled_customer_initiated_transaction. 4xx responses that carry a transaction body (e.g. HTTP 470 Declined) are decoded as a TransactionResult rather than thrown as gateway errors.

Docs & demo app

  • MeetIntheCloud-REST-Contract.md — the source-of-truth wire spec: base URLs, auth token algorithm, every header, every endpoint, request/response JSON, status & error mapping.
  • TEST-CREDENTIALS.md / HANDOFF.md — sandbox credentials and how to read the terminal's Cloud Device ID.
  • architecture.html — visual diagram of the component stack, link-at-compile-time story, and the sale call flow.
  • ExampleApp/ — a runnable SwiftUI demo (health check / sale / void / cancel), reproducible via xcodegen generate and a one-shot ./run-demo.sh.

3. App integration (ChargeVC & Settings)

Wiring the package into the live POS happened mainly in ChargeVC.swift and Setting.swift.

ChargeVC (the charge screen)

  • MITC sale path with a 15-minute request timeout in production (the terminal can sit on a prompt for a long time).
  • Status label now reads "Follow the prompts on the payment device…" during processing, and "Approved {code} {card}" on success (logging transactionId / approval / card).
  • Specific error handling — gateway, network, validation, and unknown are separated instead of one catch-all. Every error/decline path resets the button title back to "Process" so the cashier can retry; guard failures (empty credentials) restore the Process button.
  • Note field placeholder set to "Note (prints on receipt only)" for MITC merchants; password row hidden in the credit-card settings for the MITC merchant.
  • Type ambiguity fixed by module-qualifying MeetIntheCloud types.

Setting.swift (credentials & config)

  • All MITC test credentials centralized in Setting (moved out of scattered constants).
  • mitcTokenizationApiKey — returns the sandbox key for MITC_TEST, the merchant login in production.
  • Renamed merchantSecret → transactionSecret (and secured the Transaction Secret field in the UI); fixed a Merchant Key label typo.
  • Credentials now refresh on merchant switch, and MITC_TEST default lookups were simplified.
  • CreditCardSettingVC refactored from a XIB view controller into SwiftUI.

MITCTestView (environment)

  • Removed the Test/Production segment picker — environment is now auto-selected from the merchant name (MITC_TEST = sandbox, otherwise production).
  • Added a read-only display of merchant Key & Secret and AppLog.log calls around the health check request/response.

4. Refund, void & cancel flows

  • Linked refund via the gateway (refund tied to the original transaction), with amount precision fixed.
  • Void action added; ChargeVC closes automatically on a successful void.
  • Cancel button added to abort an in-flight terminal transaction, with improved refund diagnostics.
  • Receipt void/refund added from the receipt view.
  • Refund validation: rejects selecting an already-refunded transaction (amount ≤ 0) and rejects an amount exceeding the original charge — both surface as inline statusLabel messages instead of alerts.
  • Refund now correctly sets paymentType = .mitc so recordSale persists the MITC fields, and the refund responsetext carries the original reference (mitc ref:…).
  • Lookup tries tranid-first with friendly "not found" messaging; refund/void status messages simplified throughout.

5. Reporting, lookup & transaction history

  • MITC reporting API added, plus a post-failure refund transaction-detail screen.
  • CardTransactionVC modernized: data source switched from local CoreData (WebTran) to the server GetWebtran API (WebTranObj). Unsynced local WebTrans load first (appear immediately), then the server response is merged and de-duplicated by reference. Search/clear filters the cached response locally by last4 / reference / transactionid. Full dark/light mode support.
  • WebTran detail viewer added; last4 storage fixed and masked-card display corrected.
  • Pending MITC WebTrans are loaded and excluded from the download array as duplicates; item lists sort by timestamp descending (newest first).
  • Daily sales report: date pickers replaced with a compact UIDatePicker, register-code filtering restored in loadDailyTransaction, and Total Gross fixed to net out refunds.

6. Invoice & reference tracking

  • mitcInvoiceCounter — a UserDefaults-backed counter starting at 1, resetting at 999999; mitcInvoiceIncrement returns it as a zero-padded 6-digit string (e.g. 000001).
  • Retry suffix changed from a random suffix to mitcLetterSuffix — a bijective base-26 sequence (0→"", 1→"A", 27→"AA") so retries of the same invoice are distinguishable and ordered.
  • Invoice number tracked end-to-end through WebTran / CartDetail.
  • Added merchantreferencecode to the CoreData WebTran entity; documented reference / transactionid naming vs. how the TSYS portal labels them.

7. Credit card fee toggle

  • Added a toggle to disable the credit card fee entirely.
  • The fee item amount is now shown in the cart footer, with clarified footer text.
  • Setting switches left-aligned with their labels; credit-card label comments added to Setting.swift and CreditCardSettingsViewModel.
  • Fixed a cart-total reference that used newItem.qty incorrectly.

8. Error email & diagnostics

  • MITC failure detail is now emailed in all builds (not just debug); the Send Log email was reformatted and a support recipient added.
  • MITC params are included in the error-email attachment.
  • Error emails route through the Bifrost SendEmail endpoint, which now supports a real CC (reverted back to SendEmailErrorLog once Bifrost gained CC support there).
  • Debug-only additions to Settings: a school-name update and a test Bifrost URL override.

9. Mock / test mode

  • MITC mock mode added for sale/refund/void so flows can be exercised without a live terminal, including a Debug mock UI.
  • Mock/test is allowed in Release builds but restricted to the MITC_TEST merchant, so production merchants can never accidentally run mocks.

10. Infrastructure & the sync-engine merge

OdinPackageIOS & SearchBarcodeV2

  • MITC files moved out of the old NMI integration folder into their own home.
  • SearchBarcode migrated to the local SPM dependency OdinPackageIOS (renamed from OdinIOSPackage), and the app migrated from SearchBarcode (V1) to SearchBarcodeV2.
  • CoreData: Transaction.txUUID / tx_uuid renamed to uuid (with renamingIdentifier and a model version bump); ZebraSDK plist fix; .build/, *.xcuserstate, and local Claude settings gitignored.

Merged from sync-engine

Inherited work: the following came in via the sync-engine merge rather than being authored on this branch, but they ship as part of it.
  • Square payment coordinator — gap detection & banner, recovery UI, a finalize-decision planner, a response planner, and a reconcile planner; refund UI handling; persists cardHolder / note / paymentBtn; add-note flow.
  • Unified sync subsystem — sync router, wave guard & retry policy, background sync + APNs, upload budget / staging / single-flight, idempotency-key builder, exactly-once side effects, pending replay prevention. Backed by a large new test suite under OdinIpadPOSTests/SyncSubstrate.
  • FCM / push — FirebaseMessaging added, push registration updated, push-notification debug notifier.
  • UUIDv7 — transaction backfill, a 12-bit source embedded into rand_a, odinMobile as the default UUID source.
  • Diagnostics hub — Send Diagnostics email-only export, Charge Log email + payment report export, Square analytics, CSV attachments & error-email aggregation.
  • Remote Config custom targeting signals, API-path signals, chunking options, and session-throttled fetch; generated third-party Licenses.txt + generator script.
